## Prerequisites

- Node.js 20+ and npm installed
- Repository cloned locally
- Dependencies installed: `npm install`
- A `.env.local` file at the project root containing:

```env
VITE_PIN_HASH=<sha256 of your chosen 4-digit PIN>
```

**Generating a PIN hash** (PowerShell):
```powershell
$pin = "1234"
$bytes = [System.Text.Encoding]::UTF8.GetBytes($pin)
$hash = [System.Security.Cryptography.SHA256]::Create().ComputeHash($bytes)
($hash | ForEach-Object { $_.ToString("x2") }) -join ""
```

## Validation Scenario 1: Shopper Views Display and Scans QR Code (US1)

**Covers**: FR-001, FR-002, FR-003, FR-004, SC-001

**Steps**:

1. Open `http://localhost:5173` at a tablet viewport (768 × 1024).
2. Without touching the screen or keyboard, observe the display.
3. Verify within 5 seconds:
   - The Planet-provided hero image is prominently displayed in the centre.
   - A promotional headline is visible at the top of the display.
   - Supporting text is visible below the hero image.
   - A QR code is visible within the hero image.
4. Scan the QR code shown in the hero image with a phone.
5. Verify the phone navigates to the Shopper Portal destination managed by
   Planet's marketing team QR service.

**Expected outcome**: Display communicates purpose and the hero image QR code is
scannable within 5 seconds. QR destination and attribution are managed externally.

## Validation Scenario 2: Language Rotation (US2)

**Covers**: FR-010, FR-011, FR-012, FR-013, SC-003

**Steps**:

1. Navigate to `http://localhost:5173/settings`.
2. Enter the correct PIN.
3. Select **two or more languages** from the catalogue (e.g., English + French).
4. Set the rotation interval to **10 seconds**.
5. Click **Save**.
6. Navigate back to `http://localhost:5173`.
7. Observe the display for at least 30 seconds.

**Expected outcome**:
- The display alternates between the configured languages every 10 seconds.
- All configured languages appear and cycle in a repeating loop.
- Transitions are smooth with no blank screen between languages.

**Single-language check**:

8. Navigate to settings and configure **only one language**. Save.
9. Observe the display.

**Expected outcome**: Display shows only that language continuously. No rotation
occurs and no timer fires.

## Validation Scenario 3: Administrator Configures the Display (US3)

**Covers**: FR-017, FR-018, FR-019, FR-022, FR-023, FR-029, SC-004, SC-005

**Steps**:

1. From the display at `http://localhost:5173`, click the settings icon in the
   bottom-right corner **five times within five seconds**. Verify the PIN
   prompt appears.
2. Enter an **incorrect** PIN (e.g., `9999`).
3. Verify access is denied and a clear error message is shown.
4. Enter the **correct** PIN.
5. Verify the settings form is now visible.
6. Select two languages, set a rotation interval, then click **Save**.
7. Navigate to `http://localhost:5173`.
8. Verify the display reflects the saved configuration.

**Restore defaults**:

9. Repeat the tap gesture and enter the PIN.
10. Click **Restore Defaults** and confirm.
11. Navigate to `http://localhost:5173`.
12. Verify the display has reverted to the default (English only).

**Expected outcome**: PIN correctly gates access; save applies immediately; restore defaults works correctly.

## Validation Scenario 4: Offline Resilience (US4)

**Covers**: FR-007, FR-008, FR-009, SC-002

**Prerequisites**: Build and serve the production bundle (PWA requires production
mode for Service Worker registration):

```bash
npm run build
npm run preview
```

Open `http://localhost:4173`.

**Steps**:

1. Allow the page to fully load (wait for Service Worker to install — check
   DevTools → Application → Service Workers).
2. Configure two languages with a 10-second rotation interval. Save.
3. Navigate back to the display view.
4. In browser DevTools → Network, set the throttle to **Offline**.
5. Reload the page (`F5`).
6. Observe the display for at least 2 minutes.

**Expected outcome**:
- The display loads successfully from the Service Worker cache.
- Language rotation continues at the configured interval.
- The QR code is visible and visually intact throughout.
- No error messages or blank screens appear.

**Pre-load failure check**:

7. Clear the Service Worker cache (DevTools → Application → Storage → Clear site
   data).
8. While still offline, attempt to load `http://localhost:4173`.

**Expected outcome**: The browser shows a clear unavailable message (the offline
fallback page) rather than a browser default network error.

## Validation Scenario 5: Responsive Layout (FR-005, FR-006, FR-028, SC-007)

**Steps**:

Open the display at each of the following viewport sizes and verify content is
legible and QR code is visible without scrolling:

| Viewport | Orientation | Representative device |
|----------|-------------|----------------------|
| 768 × 1024 | Portrait | iPad / tablet |
| 1024 × 768 | Landscape | Tablet landscape / kiosk |
| 1920 × 1080 | Landscape | Full HD TV / large display |
| 3840 × 2160 | Landscape | 4K display |
| 1080 × 1920 | Portrait | Digital signage portrait screen |

**Expected outcome**: At all viewports, the QR code is prominently placed, all
text is legible without zooming, and no content is cropped or overflows the
viewport.

## Validation Scenario 6: Accessibility (SC-008)

**Steps**:

1. Run an automated accessibility audit on `/` and `/settings`:
   - Browser DevTools → Lighthouse → Accessibility
   - Or: `npx axe-core-cli http://localhost:5173`
2. Verify score meets WCAG 2.2 AA with no critical violations.
3. Navigate the display view using keyboard only.
4. Navigate the settings view using keyboard only (PIN entry → language
   selection → save).

**Expected outcome**: No WCAG 2.2 AA violations. Keyboard navigation is fully
functional across both views.

## Build Validation

Before any deployment, run the full build to confirm no TypeScript errors and
all assets are produced:

```bash
npm run build
```

Verify `dist/` contains:
- `index.html`
- JS and CSS chunks
- Service Worker (`sw.js` or `workbox-*.js`)
- All locale JSON files
- All image assets from `public/assets/`

Run the production preview and repeat Scenario 4 (offline check) against the
build output.
